遵循全局 `AGENTS.md`。本文件只记录重要且长期有效的项目约定，不写操作流水账和任务完成情况。开始或接手任务时读取 `YAN.md`，了解项目进度和问题；已读取且未变化时复用。

## 代码与协作

1. 尽量复用现有实现，改动围绕当前任务展开，清理确认无用的代码。
2. 项目特殊约定：[必须保持的行为或接口]

## 环境与实验

1. 代码修改限于本项目，使用指定环境，不改动全局环境和其他项目。
2. 只管理本项目启动的进程，按进程或作业编号操作，不使用批量终止命令。
3. 实验使用分配的 GPU、端口和输出目录。

## YAN.md 维护

1. 内容必须非常精简，保留项目介绍、已完成、正在进行、已发现的问题、下一步。所有大标题下的内容统一用 `1.`、`2.`、`3.`……列小点，每个部分从 `1.` 开始，项目介绍也遵循此格式。
2. 只记录实质项目进展、重要研究工作、关键实验结果及影响实验的问题，不写 Git 连接、提交同步、常规文件整理等琐事。已完成工作与实验结果合并概括，正在进行的工作单独记录；重要进展、结论或问题状态变化时更新。
3. 详细内容链接到其他 Markdown 文件，例如：[实验设计](jinghao/jiejue/1.md)、[实验结果](jinghao/jiejue/1.1.md)。正文只留简短结论，不重复展开。
4. 所有部分的条目先用一句话概括对应事项；涉及实验时再附实验详情和已有结果文件。例如：`1. [简要概括事项及已有实验结果]。实验具体：[实验设计](jinghao/jiejue/1.md)；实验结果：[结果记录](jinghao/jiejue/1.1.md)。` 无实验的条目只写概括，没有结果时不添加结果链接。
