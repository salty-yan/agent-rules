遵循全局 `AGENTS.md`。本文件只记录重要且长期有效的项目约定，不写操作流水账和任务完成情况。开始或接手任务时读取 `YAN.md`，了解项目进度和问题；已读取且未变化时复用。

2. 运行环境与命令：[虚拟环境、安装及运行方式]
3. 配置与结果：[配置、日志和输出位置]
4. 必要检查：[检查命令及通过标准]

## 代码与协作

1. 尽量复用现有实现，改动围绕当前任务展开，清理确认无用的代码。
2. 项目特殊约定：[必须保持的行为或接口]

## 环境与实验

1. 代码修改限于本项目，使用指定环境，不改动全局环境和其他项目。
2. 只管理本项目启动的进程，按进程或作业编号操作，不使用批量终止命令。
3. 实验使用分配的 GPU、端口和输出目录。

## YAN.md 维护

1. `YAN.md` 是给用户看的项目概览，必须非常精简、讲大白话，让用户一眼看懂实验在做什么、做到哪里、有什么问题。少用术语、缩写和代码名，必须使用时简单解释。
2. 固定保留“项目介绍、已完成、正在进行、已发现的问题、下一步”五个大标题，标题不编号。所有标题下都用 `1.`、`2.`、`3.`……列小点，各部分从 `1.` 开始；没有内容时写 `1. 暂无。` 项目介绍只写项目内容。
3. 实验条目按“实验标题：实验简要内容”写，不要求概括关键实验结果。例如：`1. [实验标题]：[实验简要内容]。实验具体：[实验设计](jinghao/jiejue/1.md)；实验结果：[结果记录](jinghao/jiejue/1.1.md)。` 正在进行的实验简述当前进展，下一步简述计划；问题按“处理状态：问题描述”写。详情与结果用真实的 Markdown 链接引用，没有对应文件时不添加链接，不在正文展开细节。
4. 只写重要研究工作、真实实验进展和影响实验的问题，不写 Git 连接、提交同步、常规文件整理等琐事。已完成与正在进行分开，只在重要进展或问题状态变化时更新。
